# mini-exchange web

A React + TypeScript + Vite MVP user interface for the [mini-exchange](../README.md) in-memory order book backend.

## Pages

### Submit Order (`/submit-order`)

Submit a limit order to the exchange. The form sends:

| Field | Description |
|-------|-------------|
| Broker / username | Your broker identifier |
| Customer document number | Identifies the customer represented by the broker |
| Side | `BID` (buy) or `ASK` (sell) |
| Stock symbol | 1–4 letters, normalized to uppercase (e.g. `AAPL`) |
| Unit price (USD) | Decimal string using a dot separator (e.g. `10.50`), converted to integer cents (`1050`) before sending |
| Quantity | Positive whole number |
| Order validity | `No expiration (GTC)` or a specific UTC expiration date/time |

The client order ID used for idempotent retries is generated by the UI
automatically; there is no manual input for it.

After submitting, the exchange returns an **Order ID**.
**Save this Order ID** — you will need it to check the order status later.

#### Order validity (GTC vs. expiration)

- **No expiration (GTC)** is the default. *GTC* means *Good Till Cancelled*:
  in this in-memory MVP the order stays active until it is filled, until future
  cancellation support is added, or until the backend process restarts. The UI
  sends `valid_until: null` and the order is never expired automatically.
- **Expires at specific UTC date/time** shows a date/time picker. The value is
  interpreted as **UTC** (we append `Z` directly rather than converting from the
  browser's local zone), so `2026-05-28T15:30` is sent as `2026-05-28T15:30:00Z`.
  Expiring orders are rejected if the time is in the past or equal to now.

This MVP does not implement full production-grade order-duration semantics
(IOC, FOK, day orders, scheduled expiry, etc.).

#### Unit price

Prices are entered in **USD** using a **dot** decimal separator (e.g. `10.50`).
Comma decimals such as `10,50` are rejected to avoid locale ambiguity. The UI
normalizes values to two decimals and sends the API integer cents (`10.50` → `1050`).

### Order Status (`/status`)

Look up the current status of a previously submitted order.

Required fields:

| Field | Description |
|-------|-------------|
| Broker / username | Must be the broker/user who submitted the order |
| Order ID | The ID returned by the exchange at submission |

Displayed information: order ID, broker, document number, side, symbol, unit price (formatted as decimal), quantity, remaining quantity, filled quantity, status, valid-until, and any executed trades.

#### Auto-refresh

- Off by default.
- When enabled, polls every **5 seconds**.
- Stops automatically when the order reaches a terminal status (`FILLED`, `CANCELED`, `EXPIRED`).
- This MVP uses HTTP polling. A production UI would use WebSocket or server-sent events for lower latency and reduced server load.

## Getting Started

### Install dependencies

```bash
npm install
```

### Run the dev server

```bash
npm run dev
```

The app is served at `http://localhost:5173` by default.

### Configure the API base URL

The frontend calls `http://localhost:8000` by default.

Set `VITE_API_BASE_URL` to point to a different backend:

```bash
VITE_API_BASE_URL=https://api.example.com npm run dev
```

You can also create a `.env.local` file in this directory:

```
VITE_API_BASE_URL=https://api.example.com
```
